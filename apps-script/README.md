# Google backend (экспериментальный перенос)

PostgreSQL сохранён как независимый вариант восстановления. На живом Google API
20.10.2026 проверены загрузка карты, Google-вход прежнего администратора и запись
провинции 1332 без изменения её значений (квитанция прочитана из `_operations`).
Полное регрессионное тестирование всех функций ещё не выполнено. Корневой
`app-config.js` автоматически выбирает PostgreSQL для localhost и Apps Script
для внешних хостов, включая GitHub Pages.

## Развёрнутые ресурсы

- Приватная база: https://docs.google.com/spreadsheets/d/16_DFnKy-TopNq6suwlW_13o5k4haU1JJt5YjqbGly6M/edit
- Редактор: https://script.google.com/home/projects/1N45UMVVEZ7q6zcivEOtmohMR5LKV8-80DCnNWzkywvC2WLUQih2x1jk5/edit
- API: https://script.google.com/macros/s/AKfycbxtj79njbMmtno-mv87mWNBTz_1P0liScB24orSJQoOt6mk10ciqq7alZxGLRGi9axX/exec

Таблица НЕ должна иметь общий доступ по ссылке. Содержит аккаунты, старые хеши
паролей и сообщения. API отдаёт только разрешённые поля. Доступ к скрипту и его
свойствам также не передавать игрокам. Веб-приложение исполняется от владельца,
доступ «Все»; роли проверяются серверным кодом, а не интерфейсом.

## Настройка

Файлы `.gs` загрузить в Apps Script (можно объединить в `Код.gs`), добавить
`Bridge.html` и заменить манифест `appsscript.json`. Включён расширенный Sheets API.
После обновления исходников обновить существующее развёртывание **новой версией**,
а не просто сохранить редактор. Сохранять существующий URL `/exec`.

Свойства скрипта (не добавлять секреты в Git или клиентский JS):

- `DATABASE_SPREADSHEET_ID`: ID базы выше; `setupFauxlore` задаёт его при отсутствии.
- `SITE_URL`: точный адрес статической карты; локально `http://127.0.0.1:8003`.
- `SITE_URLS`: JSON-массив разрешённых полных адресов. `setupFauxlore` при отсутствии
  задаёт локальный адрес и `https://hookerslayer.github.io/fauxlore` (плюс SITE_URL).
  Например: `["http://127.0.0.1:8003","https://hookerslayer.github.io/fauxlore"]`.
  После настройки списка менять SITE_URL при переключении устройств не требуется.
  Клиент передаёт полный адрес своей карты, сервер проверяет его по списку и
  возвращает OAuth-вход на этот адрес. Билет также привязан к исходному origin.
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`: OAuth-клиент типа «Веб-приложение».
  Разрешённый redirect URI — **полный URL API `/exec`** выше. Для тестового OAuth
  приложения добавить игровые Google-аккаунты в тестовые пользователи. Секрет
  вводит владелец самостоятельно; не пересылать его в чат.

Google-вход использует `openid email profile`, серверный обмен кода, одноразовый
билет с проверкой инициировавшего браузера. Подтверждённый Gmail/Workspace
привязывается к существующему аккаунту по email, сохраняя роль. Новый аккаунт
всегда `player`. Парольный вход и старые сессии PostgreSQL здесь не действуют.

## Локальная проверка без PostgreSQL

Из корня репозитория:

```powershell
.venv/Scripts/python.exe tools/build_google_site.py --apps-script-url https://script.google.com/macros/s/AKfycbxtj79njbMmtno-mv87mWNBTz_1P0liScB24orSJQoOt6mk10ciqq7alZxGLRGi9axX/exec
.venv/Scripts/python.exe -m http.server 8003 --bind 127.0.0.1 --directory .local/google-site
```

Открыть http://127.0.0.1:8003/ . Сервер здесь только раздаёт статические файлы;
БД и API работают на Google. Для постоянной публикации нужен статический хостинг
(не VPS). Адрес публикации должен быть в `SITE_URLS`, включая путь репозитория.
`localhost` и `127.0.0.1` — разные origins. GitHub Pages пока не опубликован этим
изменением: отдельно разместить содержимое Google-сборки, не приватные `.local`.
Проекты одного GitHub Pages-домена делят origin; разрешение API действует на
`https://hookerslayer.github.io`, а не изолирует его проекты по URL-путям.
Не раздавать корень репозитория: там могут быть приватные файлы `.local`.

`tools/build_google_site.py` также создаёт `.local/google-upload` с тремя UTF-8
текстами для загрузки в редактор. Эти тексты не содержат дампа и секретов.

## Данные и гарантии

Перенесены 16 листов: все игровые строки, связи, аккаунты и бинарные изображения
(`_blobs`, base64-блоки до 30000 символов). Старые сессии/сбросы паролей сохранены
в `_legacy_*`, но отключены. На 20.10.2026 проверено полное совпадение данных с
экспортом, включая восстановленные после XLSX-конвертации ISO-временные метки.
Два устаревших маркера temple/interest сохранены в архивных данных, API их скрывает.

Изменения выполняются под `ScriptLock`, одним атомарным Sheets batchUpdate вместе
с квитанцией команды `_operations`. Повтор с тем же ID не применяет команду дважды.
Ручные правки таблицы обходят блокировки/проверки приложения: не редактировать
одновременно с игровыми командами и не менять заголовки/ID/системные листы.
Ограничения и квоты Google сохраняются; таблица не даёт всех гарантий PostgreSQL.
Экономические расчёты пока не реализованы: их перенос сюда нельзя считать готовым.

Локальный `node apps-script/test-backend.mjs` использует приватный
`.local/google-migration/export.json` и эмуляцию сервисов. Он проверяет права,
идемпотентность, атомарный отказ, редактирование и билет входа; **не заменяет
живой тест Google API**.

## Резервная копия и два устройства

Снимок до переноса: соседняя папка `PostgreSQL-version-20261020-133050`.
В ней полный `project/`, custom-format dump, манифест, ZIP. Dump проверен через
`pg_restore --list` и реальное восстановление в отдельную временную БД: количества
строк всех 12 таблиц совпали с манифестом. Рабочая БД не менялась; временная удалена.
Повторная проверка: `python tools/verify_postgresql_backup.py <папка-снимка>`.
Приватные копии Google Drive:

- Dump: https://drive.google.com/file/d/1K3lZplOc7RQGlA70cxE5zt0uS49u-DqS/view
- Полный ZIP: https://drive.google.com/file/d/1FdLmYLRfaKR0VwHDq0I4gyoxhO95en-v/view

Git переносит только код. В Google-варианте оба устройства используют **одну**
центральную таблицу; заново импортировать PostgreSQL поверх неё нельзя. Секреты
остаются в свойствах облачного скрипта. Снимок PostgreSQL после переноса устаревает:
новые Google-изменения не синхронизируются обратно автоматически. Перед откатом
сначала сохранить новую копию таблицы и спланировать обратный перенос данных.
