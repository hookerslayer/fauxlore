## Приоритет 1 — завершить расчёт стабилизации в статистике

### Диагноз

Стабилизация сословий рассчитывается в `calculateStatePolitics()` в `economy.js`:

`стабилизация сословия = влияние × (лояльность − 0,60) × 2 × множитель статуса`

Множители статусов: Ключевое 1,5; Значимое 1; Бесправное 0,25. Стабилизация — подписанный вклад, поэтому может быть отрицательной.

В `ui.js` обновление ячеек `[data-politics-stability]` ищет ключ только в `derived.estateStability`. У строк рас и религий такого ключа нет: они получают `—`. При этом групповые блоки для общей стабильности рассчитываются как взвешенная по населению лояльность групп, нормированная относительно 50%; блок религии дополнительно получает 0,2. Отдельные значения стабилизации для рас/религий в UI не формируются. Это причина пустой колонки.

### Предлагаемая формула групп

Для каждой присутствующей расы и религии определить долю населения `влияние группы = население группы / население всех групп этого типа в государстве`. Затем использовать ту же интерпретацию вклада, что и в общей формуле:

`стабилизация группы = влияние группы × (эффективная лояльность − 0,50) × 2`

Для религий этот вклад не включает базовую добавку 0,2: она относится к агрегированному блоку религий, а не к отдельной религии. В эффективной лояльности участвует сохранённая лояльность и только уже действующие модификаторы. Для рас/религий сейчас это сохранённая лояльность; налоговое давление и статусные амбиции к ним не применять.

Общий блок каждого типа остаётся ограниченным 0…1. Формула государства сохраняет принятый вид: среднее трёх блоков — рас, религий и сословий — после ограничения каждого блока. Сословный блок включает все пять сословий и базу 0,5; блок религий включает базу 0,2. Нельзя складывать ограниченные показатели групп вместо исходного взвешенного вклада.

### Этапы

1. [x] В `economy.js` возвращаются карты `raceStability` и `religionStability` наряду с `estateStability`; расчёт группового вклада выделен в чистую функцию. Рассчитываются только присутствующие группы с ненулевым населением.
2. [x] `ui.js` заполняет текущие колонки рас и религий со знаком и единицей «п.п.»; отсутствующее значение показывается как `—` с подсказкой. Заголовки стабилизации объясняют смысл вклада.
3. [x] В `docs/economy.md` добавлены формула и связь с агрегированными блоками; отметка о необходимости формализации стабилизации рас/религий снята.
4. [x] Вручную проверены примеры 50%, 60% при доле 20%, отрицательный вклад, смешанные группы и отсутствие категории; общие блоки складываются из тех же исходных вкладов и UI не меняет расчёт государственной стабильности.

### UI

Сохранить существующую вкладку «Государства → [государство] → Статистика» и таблицы «Сословия», «Расы», «Религии». Не добавлять новую панель и не растягивать блоки. В каждой таблице оставить колонку «Стабилизация» рядом с лояльностью. Добавить короткую подсказку к заголовку: «Вклад группы в стабильность государства; знак показывает повышение или снижение». Саму стабильность государства показывать в существующей карточке «Состояние государства». Соблюдать компактные таблицы, заметные промежутки между блоками, тёмные фоны и жёлтый акцент. На узком экране прокручивается таблица, а не вся вкладка.
