## Этапы 1–2 — выполнены; этап 3.1 — выполнен

Применены и проверены миграции `20261023071806_state_indicators_and_food_crime`, `20261023072500_state_indicator_dispatch_permissions`, `20261023072818_urbanization_calculated_population_growth`. Локальная схема содержит те же изменения. CLI Supabase в окружении отсутствует: миграции созданы через подключённый MCP, локальные имена взяты из фактической серверной истории.

Серверные показатели выдаёт API `my|admin/states/:id/indicators`. Только администратор меняет неотрицательный целый лимит; до/после и государство сохраняются в `operations` вместе с актором и идентификатором запроса. Начальное значение 1000. Внутренние расчётные функции не доступны клиентским ролям; обработчик API доступен `authenticated` и проверяет аккаунт/закрепление государства. При проверке браузером обнаружен и исправлен недостающий грант этому обработчику; добавлен тест от роли `authenticated`.

Показатели населения/развития исключают море и считают собственные территории, включая оккупированные. Пропуски развития не подменяются нулями; пустое государство отдельно получает 0. Стабильность считает все пять сословий и индивидуальные ставки; исправлено расхождение серверной ценности провинции. Снимок формируется до ежегодных изменений лояльности и жизненного цикла персонажей. Изменение преступности применяется только после завершения производства и продовольственного отчёта всех государств.

Урбанизация уменьшает только расчётный прирост по утверждённой модели; сервер передаёт множитель в данные владельца провинции. Порядок: население × 3% × расовый множитель × штраф урбанизации → округление по провинции → сумма. Фактическое население/запас рекрутов не изменяются.

## Решение для этапов 3–4 — утверждено владельцем

23.10.2026 владелец ответил «Да, утверждаю» на предложенные ниже коэффициенты. Модель перенесена в `docs/economy.md` и реализована. Коэффициенты дополнительных эффектов преступности выбраны Codex по явному разрешению в плане.

`o = MAX(0, развитие − лимит) / лимит`; прибавка коррупции от перегрузки `MIN(3, o)` п.п./ход. Преступность от перегрузки дополнительно не повышать, чтобы не дублировать поправку стабильности. Для лимита 1000 и развития 1001/1500/2000/4000 это +0,001/+0,5/+1/+3 п.п. При нулевом лимите и положительном развитии — предельные +3 п.п., при обоих нулях — 0. При пропущенном развитии показывать предупреждение и использовать только известную сумму.

Поправка стабильности к коррупции: ≥75% → −1; ≥50% → 0; ≥25% → +1; <25% → +2 п.п. Общий шаг ограничить −1…+3 п.п., значение коррупции 2…90%. Примеры: развитие 1500/1000, стабильность 60%, коррупция 20% → 20,5%; развитие 4000/1000, стабильность 20%, коррупция 89% → 90% (шаг +3, фактически +1). Стабильность и коррупция берутся на начало хода.

Бонус Знати и Духовенству вычисляется как `MIN(0,15; коррупция / 6)` к эффективной лояльности следующего хода: коррупция 20% даёт +3,333 п.п., 90% — +15 п.п. Бонус не накапливается повторными прибавлениями к сохранённой базовой лояльности.

## Этапы 3–5 — завершены 23.10.2026

Применены миграции `20261023073849_approved_corruption_and_crime_effects` и `20261023074517_restore_economy_config_dispatch`; актуальные определения и история сверены с локальной схемой. Вторая миграция восстанавливает маршрут редактирования констант, потерянный более ранним переписыванием диспетчера. Исправление найдено проверкой реального публичного RPC.

Реализованы:

- Динамика коррупции от перегрузки и начальной стабильности, точность хранения 0,00001 п.п., границы 2–90% и шаг −1…+3 п.п. Начальные и конечные значения, оба вклада, фактическое изменение и использованные коэффициенты сохранены в отчёте. Снимок включает развитие, лимит и число пропусков.
- Ненакопительный бонус эффективной лояльности Знати/Духовенства. Начальная коррупция определяет стабильность текущего хода, конечная — лояльность следующего. Повторного пересчёта внутри хода нет.
- Однократные налоговые вычеты до деления казн: коррупция, затем преступность. Валовой налог, вычеты, чистый налог и доли казн доступны по государству и каждой провинции. Для оккупации используются ставка и показатели получателя; производство по-прежнему использует преступность владельца и один штраф.
- Эффекты преступности с коэффициентами 0,25 / 0,50 / 0,50: налог / прирост населения / бонус прироста рекрутов. Лимит рекрутов не меняется, сохранённое население и запас рекрутов не зачисляются.
- 13 редактируемых коэффициентов в группах «Население», «Управление», «Налоги», «Преступность» с серверной валидацией, аудитом и повтором запроса. Исправлены старые неверные пути полей модификаторов типов и добавлены видимые заголовки групп.
- Начальные показатели, изменения и налоговые вычеты в экономическом отчёте. Формулы раскрываются по нажатию на показатели состояния; лимит редактирует администратор. Статистика и отчёты читаются на телефоне без горизонтального сдвига основных чисел. Открытые административные карточки обновляются при фоновой ревизии.
- Исправлен адаптер игрока: сохраняются серверные множители урбанизации/преступности, коррупция и ID категорий; начальные показатели берутся из API показателей, а не из устаревшей категории карты.
