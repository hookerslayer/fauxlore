# Правила интерфейса Fauxlore

Эти правила обязательны при создании и изменении любого UI проекта.

## Компоновка

- Между самостоятельными блоками всегда должен быть визуально заметный отступ. Не размещать соседние карточки, панели, формы и таблицы вплотную.
- Если блок не содержит большой объём текста или широкую таблицу, не растягивать его на всю ширину контейнера. Выбирать компактную ширину и группировать связанные элементы.
- Кнопки внутри вкладок меню не растягивать на всю ширину контейнера. Располагать их компактно рядом с содержимым; на мобильном экране сохранять удобную область нажатия.
- Ширину на всю область использовать только там, где это нужно содержимому (например, большой таблице или длинному тексту), а не по умолчанию.
- Внутренние отступы карточек должны оставлять небольшой зазор между контентом и рамкой, обычно 10–12 px. Заголовки блоков не должны сохранять большие браузерные отступы по умолчанию: задавай компактный интервал между заголовком и содержимым через сетку/контейнер.

## Единые возможности

- Любое действие с игровыми данными, доступное игроку, должно быть доступно администратору при просмотре соответствующего государства. Администраторские инструменты сверх этого правила могут оставаться отдельными.
- Изменения формы сохранять явной кнопкой «Сохранить», если пользователь редактирует несколько связанных значений в одном разделе; не отправлять каждое поле отдельно без указания.
- Компактность не должна ухудшать читаемость: таблицам разрешено горизонтально прокручиваться на телефонах, а подписи и элементы управления должны оставаться различимыми.

## Мобильные устройства

- Проверять каждый новый экран и диалог при ширине 320–390 px: шапка и навигация не должны занимать большую часть высоты, таблицы прокручиваются внутри своего блока, а страница не получает лишнюю горизонтальную прокрутку.
- Действия внутри вкладки, включая найм, сохранение и отправку комментария, сохраняют текущую позицию прокрутки. Полная перерисовка раздела не должна возвращать игрока в начало.
- Управление картой и войсками должно работать касанием: фишки имеют удобную область нажатия, панели действий и маршрута помещаются в экран, а завершение действия доступно видимой кнопкой без клавиатуры.
- Всплывающие подсказки не перекрывают рабочую область на всю высоту. Формы и кнопки в диалогах должны оставаться доступны при прокрутке содержимого.

## Числа и расчёты

- Не показывать дробные значения для населения, рекрутов, ресурсов и денежных сумм. Производные количества и суммы округлять вниз до целого на сервере и в клиентских расчётах (`floor` / `Math.floor`), а не обычным округлением или округлением вверх.
- Дробные значения оставлять только там, где это сама игровая величина (например, процент, коэффициент или динамическая цена единицы ресурса); динамическую цену показывать с точностью до двух знаков. Итоговые начисления и объёмы после расчёта всё равно приводить к целому вниз.
