# PostgreSQL и API

Приложение теперь требует API. `python -m http.server` не обслуживает базу и
авторизацию. Для локального запуска Windows:

```powershell
powershell -ExecutionPolicy Bypass -File tools/start-local.ps1
```

Открыть http://127.0.0.1:8002 . Скрипт создаёт `.venv`, скачивает переносимые
официальные бинарные файлы PostgreSQL 17 от EDB, запускает их ТОЛЬКО на
127.0.0.1:55432 (не системная служба) и запускает FastAPI. Первый запуск
долгий из-за размера архива. Уже установленный PostgreSQL тоже подходит:
задайте `DATABASE_URL`, тогда загрузка/запуск переносимого PostgreSQL пропускаются.

Если Python не в PATH, создайте .venv доступным интерпретатором вручную.
Существующий сервер на 8001 можно оставить: новый интерфейс открывать на 8002.

Linux / готовый PostgreSQL:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock.txt
export DATABASE_URL='postgresql://fauxlore:PASSWORD@127.0.0.1:5432/fauxlore'
export APP_ORIGIN='http://127.0.0.1:8002'
python -m uvicorn server.app:app --host 127.0.0.1 --port 8002
```

Секреты и кластер в `.local/`, они не попадают в Git и НЕ раздаются приложением.
Не копировать работающий каталог pgdata для миграции — использовать pg_dump.
API использует отдельного владельца БД без SUPERUSER, не аккаунт postgres.

## Схема и исходные данные

`schema.sql` обновляет схему при запуске. На первом запуске импортируются 5724
провинции. Имена по умолчанию «Провинция ID»; население вычисляется как дворы × 4.
JSON остаётся источником геометрии для осознанного импорта.
Перезапуск не импортирует всё заново и не стирает пользовательские изменения.

```sh
python -m server.manage init
python -m server.manage import-map
```

Повторный import-map обновляет геометрию существующих ID, сохраняет имена,
не удаляет автоматически исчезнувшие ID с возможными игровыми связями.
Бинарная геометрия и тайлы остаются статическими файлами, не строками пикселей.

`map_categories(layer,id,name,color)` и `province_values(province_id,layer,category_id)`
хранят категории states/races/religions/resources/trade/climate. Справочники рас,
религий, ресурсов и климатов заполняются при инициализации пастельной палитрой.
Администратор назначает значения в режиме редактирования карточки провинции.
Дворы — целое число, население = дворы × 4; развитие — целый уровень.
Тип провинции обновляется по маркерам столицы/города и владению государством,
если администратор не задаёт собственный тип. Контроль хранится отдельно от
владения; на слое государств оккупация показана диагональной штриховкой цвета
контролирующего государства. Налоги, производство, склад и напряжённость
показываются как пустые значения до появления экономической модели.

## Аккаунты

Регистрация всегда создаёт player. Admin назначается только оператором:

```sh
python -m server.manage create-admin --email you@example.com
# Или повысить уже зарегистрированного пользователя:
python -m server.manage promote-admin --email you@example.com
```

Пароль вводится через getpass, не аргумент командной строки. Общих паролей и
автоматического администратора нет. Пароли хешируются Argon2; сессии — случайные
токены в HttpOnly/SameSite cookie, в БД только SHA-256 токена. Права проверяются
сервером. Изменения настроек карты сохраняются в аккаунт, гостевые — localStorage.

Локальный сброс пароля: письмо `.eml` сохраняется в `.local/mail/`, открыть его
на сервере и перейти по ссылке. SMTP не имитируется сообщением «доставлено».
Ссылка действует 30 минут, одноразовая; сброс отзывает все сессии.
Для реальной почты настроить SMTP_HOST/PORT/FROM/USER/PASSWORD и APP_ORIGIN.
Связь игрока с государством назначается оператором; после этого владелец может
переименовывать провинции своего государства:

```sh
python -m server.manage assign-state --email player@example.com --state "Название государства"
```

## Развёртывание

Перед публичным размещением: HTTPS reverse proxy, COOKIE_SECURE=1,
APP_ENV=production, явный APP_ORIGIN, SMTP, отдельный DB-пользователь, закрытый
порт PostgreSQL и внешние резервные копии. Не публиковать dev http.server из
корня проекта: он не использует whitelist и способен раздать локальные файлы.
Приложение разрешает только перечисленные публичные файлы/иконки/тайлы.
Для нескольких worker'ов заменить локальный limiter общим хранилищем;
здесь один процесс Uvicorn. Подтверждение email пока не реализовано.

Локально Ctrl+C останавливает API. PostgreSQL остаётся доступен для последующей
работы; его можно корректно остановить отдельно:

```powershell
& ./.local/pgsql/bin/pg_ctl.exe -D .local/pgdata -m fast stop
```

`requirements.txt` — прямые зависимости, `requirements.lock.txt` — проверенные
версии вместе с транзитивными зависимостями для воспроизводимого запуска.

## Снимок базы и перенос между устройствами

Для переноса актуальных данных используйте логический снимок PostgreSQL, а не
копию каталога `.local/pgdata`. Снимок содержит структуру и данные таблиц,
индексы и последовательности, включая аккаунты, игровые настройки, сообщения,
реакции и изображения/аватары, сохранённые в `bytea`. Он фиксирует состояние на
момент экспорта; последующие изменения в файл автоматически не попадут.

Снимок не содержит внешние файлы проекта, настройки SMTP и системные роли
PostgreSQL. Код, карту и тайлы переносите отдельно вместе с проектом; на новом
устройстве создайте роль приложения и пустую БД, затем восстановите снимок.
Пароли ролей PostgreSQL лучше задать заново. Не храните дампы с пользовательскими
данными в публичном Git-репозитории.

На Windows, после запуска локальной БД через `tools/start-local.ps1`, выполните
из корня проекта в PowerShell:

```powershell
$backupDir = '.local/backups'
New-Item -ItemType Directory -Force $backupDir | Out-Null
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$dbUrl = (Get-Content '.local/database.json' -Raw | ConvertFrom-Json).url
& '.local/pgsql/bin/pg_dump.exe' --format=custom --no-owner --no-acl `
  --file "$backupDir/fauxlore-$stamp.dump" --dbname $dbUrl
if ($LASTEXITCODE -ne 0) { throw 'Экспорт PostgreSQL завершился с ошибкой' }
```

Скопируйте полученный `.dump` на другое устройство через закрытое хранилище,
например Google Drive, или переносной диск. Не загружайте его в GitHub: в нём
есть хеши паролей и личные сообщения игроков.

На целевом устройстве сначала настройте PostgreSQL и создайте пустую БД `fauxlore`
с владельцем-приложением, затем укажите её адрес в `$env:DATABASE_URL`. Проверьте,
что адрес указывает именно на целевую БД: следующая команда заменяет объекты с
совпадающими именами данными снимка.

Для обычного переключения между двумя Windows-устройствами:

1. Получите актуальный проект из GitHub вместе с submodule:
   `git clone --recurse-submodules https://github.com/hookerslayer/fauxlore.git`.
2. Скопируйте последний `.dump` из закрытого хранилища в папку проекта.
3. Один раз запустите `tools/start-local.ps1`, дождитесь открытия API и нажмите
   Ctrl+C. Это подготовит Python-зависимости и локальный PostgreSQL на новом
   устройстве. Запущенный PostgreSQL останется доступен.
4. Восстановите снимок в локальную БД по команде ниже, затем снова запустите
   `tools/start-local.ps1`.

При следующем переходе сначала экспортируйте свежий `.dump` на текущем
устройстве. Передавайте файл вместе с актуальным проектом; не продолжайте менять
одну и ту же базу независимо на обоих устройствах — снимок переносит состояние,
но не объединяет изменения.

```powershell
$dbUrl = (Get-Content '.local/database.json' -Raw | ConvertFrom-Json).url
& '.local/pgsql/bin/pg_restore.exe' --clean --if-exists --no-owner --no-acl `
  --exit-on-error --dbname $dbUrl 'ПУТЬ-К-СНИМКУ.dump'
if ($LASTEXITCODE -ne 0) { throw 'Восстановление PostgreSQL завершилось с ошибкой' }
```

Перед восстановлением поверх уже используемой базы сначала сделайте её отдельный
снимок. После восстановления запустите приложение и проверьте вход, провинции и
чат. Удалённая БД сама по себе не синхронизируется: перед переходом на другое
устройство экспортируйте новый снимок, а там восстановите его.

На Linux для экспорта/восстановления используются те же `pg_dump` и `pg_restore`;
версия PostgreSQL должна быть совместима. Не копируйте Windows-бинарники или
работающий каталог `pgdata`.

Тесты (на отдельной временной схеме той же БД, данные игры не изменяют):

```sh
python -m unittest server.test_api -v
node tools/test_map_tools.mjs
node tools/test_view_region.cjs
```
