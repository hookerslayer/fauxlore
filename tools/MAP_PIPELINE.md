# Подготовка карты Fauxlore

`build_province_mask.py` требует Python, NumPy и Pillow:

```powershell
python tools/build_province_mask.py fauxlore.png map-data
```

## Геометрия

1. Изображение читается в исходном разрешении. Бежевые непрозрачные пиксели
   (`R >= 230, G >= 200, B >= 180, A >= 128`) — семена суши. Полностью прозрачные
   пиксели — семена моря. Остальные пиксели считаются контурами/помехами.
   Пороги подобраны под текущий файл, а не являются универсальным распознаванием.
2. Связные компоненты выделяются отдельно для суши и моря с четырьмя соседями.
   Однопиксельные бежевые соединения сохраняются. Диагональное касание само по
   себе не соединяет области. Самая большая компонента прозрачности, доходящая
   до края PNG, исключается как внешнее пространство. Это допущение для данного
   файла: остальные компоненты у края сохраняются как обрезанные морские
   провинции. Если контур моря разорван в сторону внешнего фона, автоматически
   отделить это море от фона невозможно — нужно исправить исходный контур.
3. Отдельные сухопутные компоненты с исходной площадью 1–3 пикселя считаются
   артефактами и исключаются из семян. Их пиксели добавляются к области
   распределения контуров. Остальные ID сохраняются: в нумерации остаются
   пропуски. Узкая перемычка внутри большой компоненты не удаляется. Морские
   компоненты этот фильтр не затрагивает. Удалённые ID, координаты и получатели
   пикселей записываются в `retired_land_artifacts` в отчёте.
4. На пикселях контуров запускается одновременное расширение семян с четырьмя
   соседями. Каждый пиксель получает ближайший ID по расстоянию вдоль контура;
   при равенстве выигрывает меньший ID. Толщина линий может различаться.
   Исходные пиксели провинций не переназначаются, внешний фон не заполняется.
5. Изолированные пиксели контуров без пути к семенам назначаются ближайшей
   провинции по евклидову расстоянию. При равенстве расстояний — меньшему ID.
   Назначения вычисляются независимо, до записи в маску. Их число учитывается
   в отчёте. Ни одного исходного пикселя контура с ID 0 оставаться не должно.
   Остальные малые области сохраняются для проверки.

## Результаты

После распределения контуров генератор удаляет морские фрагменты до 64 пикселей,
касающиеся края изображения. Далее строит граф водных провинций по общим
пиксельным рёбрам: водная сеть с выходом к внешнему фону или краю — `sea`,
замкнутая сеть внутри суши — `lake`. Реки в отдельном изображении не считаются
морским выходом. Классификация геометрическая: замкнутые внутренние моря также
попадут в озёра, если для них позднее не задать ручное исключение.

Морские провинции до 64 пикселей объединяются с соседним морем по наибольшей
суммарной общей границе. Соседние микропровинции обрабатываются группами,
чтобы исключить циклы переназначения. Озёра сохраняются независимо от размера.
Сохранившиеся ID не перенумеровываются. Удалённые ID и получатели записываются
в `retired_small_sea_artifacts` отчёта. Метаданные используют три типа:
`land`, `sea`, `lake`.

После изменения маски необходимо пересобрать упакованную текстуру с реками
и тайлы:

```powershell
python tools/merge_river_mask.py map-data/province-ids.png rivers.png map-data/province-ids-rivers.png
python tools/build_map_tiles.py
python tools/audit_provinces.py
```

`build_map_tiles.py` также читает `relief.png` (серый RGBA/палитровый PNG,
того же размера, что карта). В итоговых тайлах RGB по-прежнему хранит ID,
старший бит alpha — маску рек, остальные 7 бит — интенсивность затемнения
рельефа с учётом прозрачности исходника. Промежуточный
`province-ids-rivers.png` сохраняет прежний формат: alpha только для рек.
Шейдер вычисляет `base * (1 - 0.6 * darkness)` — Multiply с opacity 60%.
Выделение, реки и контуры рисуются после рельефа. Данные рельефа привязаны
к исходным пикселям и не расширяются при зуме. После изменения relief.png
достаточно повторно запустить `python tools/build_map_tiles.py`.

- `province-ids.png`: RGB PNG исходного размера, ID = `(R << 16) | (G << 8) | B`.
  ID 0 — внешняя область. PNG не следует масштабировать со сглаживанием,
  перекодировать в JPEG или читать по визуальным цветам превью.
- `provinces.json`: ключ цвета, ID, `kind` (`land`/`sea`), площадь в пикселях,
  исходная площадь, bbox с включёнными крайними пикселями, средний центр площади.
  Средний центр может находиться вне вогнутой провинции: для подписей нужен
  отдельный подбор внутренней точки. Формат близок к предыдущему проекту,
  но готовая интеграция с прежней базой не предполагается.
- `province-preview.png`: уменьшенное диагностическое изображение с разными
  цветами провинций; `terrain-preview.png` показывает классификацию суши и моря.
- `report.json`: результаты проверок и малые области, требующие просмотра.

## Отображение без исходной подложки

Область просмотра задаётся в `map-data/view-region.json`: `bounds` содержит
`[minX, minY, maxX, maxY]` в координатах исходника, верхние границы исключены.
Текущая область `[2100,2700,4800,5110]` подобрана по скриншоту пользователя.
Камера и общий вид ограничены этим прямоугольником, шейдер отсекает внешние
пиксели, поиск и статистика используют провинции с пересекающимися bbox.
Загружаются только пересекающие область тайлы: сейчас 4 вместо 25.
Пограничные провинции могут быть показаны частично; их ID и полная площадь
сохраняются. PNG и глобальные метаданные не обрезаются. Для расширения области
достаточно изменить bounds и перезагрузить страницу.

Исходный `fauxlore.png` нужен только при подготовке. На сайте цвета заливок
вычисляются по ID и данным государства/типа территории. Граница рисуется по
переходам между соседними ID, а берег — по переходам land/sea. Старые чёрные
контуры больше не создают пустот и не задают толщину новых линий.

Это отказ от видимой растровой подложки, но сама техническая ID-маска всё ещё
растровая. Для полностью векторной карты нужно извлечь общие рёбра провинций,
построить кольца с отверстиями и упрощать общие рёбра согласованно. Независимое
упрощение каждого полигона может снова создать щели. Бежевые перемычки следует
считать топологическими связями, а не автоматически удалять как шум.

Для 10000×10000 не стоит копировать старый попиксельный Canvas-рендер целиком:
один RGBA-слой занимает 400 МБ. Практичный дальнейший шаг — тайлы ID-маски и
WebGL с nearest-фильтрацией и таблицей цветов либо векторные тайлы. Необходимо
сохранить исходные ID при генерации уровней масштаба.

## Ограничения

Алгоритм не восстанавливает авторский замысел при разрыве контура: две области
сольются. Самые крупные и самые маленькие компоненты нужно проверить визуально.
ID детерминированы для неизменного источника, но могут сдвинуться после изменения
контуров. После привязки игровых данных нужно фиксировать ID и сопоставлять
области между версиями, а не безусловно перегенерировать нумерацию.
