Production обслуживается VPS и базой `fauxlore_production_candidate`. Предыдущие результаты и ограничения нагрузки описаны в `vps/PERFORMANCE_TODO.md`.

Это приблизительные одиночные измерения, не статистика и не оценка нагрузки многих игроков. Стена измерена дважды. Некоторые панели продолжают загружаться после первичной отрисовки. Другие государства, пользовательские роли, браузеры и сети могут давать иные результаты.

Серверные измерения приведены отдельно: большинство сделано на восстановленной изолированной базе `fauxlore_restore_filtered`, данные которой могут отличаться от production. В частности, налоговая эффективность вызывает резолвер постоянных модификаторов для провинций; также расчёт рекрутов вызывает этот резолвер для локальных модификаторов. Резолвер формирует список постоянных модификаторов, и это может повторяться многократно. Доля каждого участка в задержке пока не доказана профилированием.
- Ранее похожая проблема проверки контроля в военном снимке была частично устранена fast path; прежние результаты и ограничения описаны в `vps/PERFORMANCE_TODO.md`.
- Возможный путь: вычислять общую часть модификаторов один раз на сервере и применять её повторно. Сохранить точную семантику локальных областей, рас, религий, ресурсов и ограничений; при необходимости использовать прежний путь для сложных случаев. Сравнить результаты до и после на изолированной базе для разных комбинаций модификаторов и проверить права.

### Совмещение показателей с финансовым прогнозом

- Финансовый projection endpoint уже загружал показатели на сервере для расчёта, тогда как интерфейс экономики параллельно запрашивал те же показатели отдельным endpoint. При открытии вкладки экономики игрока также пропускается предварительный запрос показателей из навигационного обработчика. Старый backend остаётся совместим благодаря fallback на прежний endpoint, если поле отсутствует. Данные рассчитываются и проверяются сервером; новый клиент не передаёт рассчитанные показатели обратно.

## Production-выпуск (3 ноября 2026)

Подготовленный набор оптимизаций выпущен в `fauxlore_production_candidate`. До изменения сохранены PostgreSQL 17 custom dump, schema dump с определениями/владельцами/ACL функций, копии трёх worker-файлов и Nginx-конфигурации. Worker заменён атомарно до удаления поля `garrison`; восемь миграций `20261103144225`–`20261103153423` применены одной транзакцией с `ON_ERROR_STOP`, все проверки миграций завершились без ошибок. Nginx переключён после успешного `nginx -t` на `/opt/fauxlore/releases/performance-finance-20261103`; старый статический каталог и backup сохранены.

После переключения read-only production smoke дал: карта HTTP 200 (1 846 провинций, 546 мс), календарь HTTP 200 (14 мс), список Стены с `defer_media` HTTP 200 (24 мс); анонимный запрос дипломатического снимка HTTP 401, что ожидается по авторизации. Развёртывание не устраняет открытый вопрос производительности. На изолированной паре второй запрос занимал 5,23 с, а короткая серия на VPS проходила при 100% общей загрузке CPU. Продолжать целевое профилирование на копии и не увеличивать таймауты как замену поиску узкого места.
