# Тестовый API для переноса

Актуальное состояние: на VPS дополнительно подготовлены изолированные службы
PostgREST и серверный мост сессий. Они обслуживают 27 имён RPC из клиента и
слушают только loopback; это ещё не публичное развёртывание. Гостевая карта,
календарь и стена проверены в браузере, как и обзор, экономика и торговля от
имени тестового игрока. Не все действия и настоящий вход через Google
проверены или завершены.

`postgrest_rollback.conf` задаёт обязательный откат каждого запроса для
отдельного тестового экземпляра; `test_postgrest_rollback_db.py` проверяет
запись журнала, настройки вложений и изменение ресурса, а также права и откат.
Эти службы предназначены только для копии `fauxlore_restore_filtered` и не
заменяют проверку перед переключением на рабочую базу.

`preview.py` обслуживает только гостевые GET-запросы к тестовой копии базы:
`/health`, `/map`, `/map/revision`, `/auth/me` и гостевые `/wall/*`.
Он выполняет запросы в транзакции только для
чтения от PostgreSQL-роли `anon`. Это не готовый API: вход, изменение данных,
остальные RPC и серверные проекции пока не реализованы.

Сервис `fauxlore-preview.service` слушает только 127.0.0.1:18080 и использует
локальный PostgreSQL через peer-аутентификацию от системного пользователя
`fauxlore_preview`. Его нельзя публиковать в интернет или направлять на рабочую
базу. Роль базы должна иметь право переключаться на `anon` и не должна иметь
самостоятельных прав на игровые таблицы. При восстановлении дампа с `--no-acl`
необходимо отдельно ограничить и проверить права всех ролей и функций.

Копия базы может устаревать, а архив содержит закрытые данные пользователей.
Не добавляйте дампы и секреты в репозиторий. Пользователь сообщил, что отключил
страницу на GitHub, и явно попросил не сверять актуальность базы перед переходом;
используется ранее согласованный снимок. Перед переходом остаются необходимые
настройки прав и рабочего OAuth.

`test_database_access.sql` проверяет гостя, игрока и администратора на тестовом
снимке в транзакции с откатом. Тест подставляет проверенные идентификаторы из
копии базы, но не проверяет настоящий Google OAuth. Выполнение ограничено именем
тестовой базы. `test_projection_adapter.mjs` проверяет подготовленный интерфейс
серверного расчёта; реальный транспорт и авторизация VPS пока не подключены.

`google_identity.py` — часть тестового прототипа проверки подписанного Google ID
token и поиска существующего профиля по Google `sub`. На изолированной копии
добавлена регистрация нового пользователя: она не связывает существующие
аккаунты по совпадению email. `test_google_identity.py` и
`test_auth_stack_db.py` проверяют старого и нового пользователя с тестовыми
подписями, без настоящих учётных данных Google; изменения теста откатываются.
`session_status_test.sql` дополняет права тестовых сервисов проверками блокировки,
удаления и подтверждённой Google-идентичности. Для повторной подготовки копии
сначала применяются `session_schema_test.sql` и `auth_role_test.sql`, затем
`google_registration_test.sql` и `session_status_test.sql`; первые файлы
отзывают общие права на функции тестовой схемы. Проверка — `test_session_status.sql`.

`oauth_flow.py` и `google_callback.py` — не подключённое к API ядро OAuth:
одноразовое состояние, привязка к браузеру, PKCE, обмен кода и проверка ID token.
Временное состояние хранится в памяти одного процесса: перезапуск прерывает вход,
несколько рабочих процессов его не разделяют. Это не готовое развёртывание:
HTTP-обработчики и сессии протестированы с имитацией ответов Google, но нужны
настройки Google Cloud, проверка регистрации и входа с реальным Google, а также
подготовка к рабочему развёртыванию. Сервис `fauxlore-auth-test.service` не включён и реальные учётные
данные Google на сервер не переносились.

`rpc_app.py` запускает на 127.0.0.1:18083 отдельный тестовый API для вошедших.
Он связывает запрос с серверной сессией, позволяет читать свой профиль,
список государств, уведомления, настройки и журнал, а также сохранять заметку
владельца или администратора журнала с проверкой прав и источника запроса.
Этот API неполный и не опубликован через Nginx. Права и запись проверяются на
изолированном снимке, в том числе тестом записи с откатом `test_journal_write.sql`.

`tools/build_vps_preview.py` создаёт отдельную гостевую сборку в `.local`, без
изменения обычной конфигурации сайта. Nginx `nginx-preview.conf` слушает только
127.0.0.1:18084 и проксирует гостевые запросы к локальному API. Сборка не
поддерживает вход и игровые изменения и не должна публиковаться в интернет.

`vps-client.js` — отдельный незавершённый клиент будущего VPS API. Он не включён
в рабочей конфигурации сайта; неподдерживаемые операции отклоняются. Для полного
перехода нужно проверить оставшиеся игровые сценарии, настроить Google OAuth и
безопасное проксирование и провести сквозные проверки до публикации.
# Локальная проверка Google OAuth

`auth_local_app.py` и `nginx-oauth-local-test.conf` предназначены только для
короткого теста по SSH-туннелю: `http://localhost:18093/auth/google/callback`.
HTTP допускается исключительно для указанного localhost и только при явном
тестовом флаге; обычный сервис требует HTTPS. Nginx слушает loopback, отключает
access log и проверяет Origin. Сервис использует копию базы и изолирован от
публичного сайта; секрет Google хранится только в `/etc/fauxlore/` и передаётся
через systemd credential, не в репозитории.

Для настоящего Google-входа владелец должен разрешить локальный redirect URI
в текущем Google OAuth-клиенте и самостоятельно создать и установить дополнительный
client secret. Старый redirect и старый secret Supabase нужно сохранить. После
проверки остановить тестовый сервис и SSH-туннель. Этот тест не является
переключением сайта и не заменяет отдельные проверки перед запуском.

Реальный вход Google на локальном маршруте проверен: существующий профиль
администратора открылся на копии базы, затем тестовые сессии отозваны. Штатная
кнопка входа и её всплывающее окно также успешно проверены в браузере.
Тестовый OAuth-секрет, отобразившийся в техническом выводе, заменён владельцем;
вход через локальную тестовую кнопку с новым секретом успешно проверен.
Прежний секрет Supabase оставлен действующим.
