## Получение и запуск на другом устройстве

```sh
git clone --recurse-submodules https://github.com/hookerslayer/fauxlore.git
cd fauxlore
python -m http.server 8001
```

Открыть http://localhost:8001/ . При обычном клонировании без submodules:

```sh
git submodule update --init --recursive
```

Сервер запускать из КОРНЯ fauxlore. На прежнем устройстве порт 8000 обслуживал
старый проект, поэтому для новой карты был запущен отдельный сервер на
127.0.0.1:8001. Эти процессы не переносятся на другое устройство.
Для просмотрщика не нужны Node.js, сборка, Supabase или внешние JS-библиотеки.
Нужен современный браузер с WebGL 2.

## Что изучено в старом проекте

Старый проект клонирован в `sixiemeterre_northeast/`, затем зарегистрирован
как Git submodule, зафиксирован на коммите `d4027a4` (полный SHA в gitlink).
Его код сегодня не менялся. Это референс; новый сайт НЕ реализован на его базе
целиком и НЕ должен автоматически обращаться к его рабочей базе Supabase.

Архитектура старого проекта: статические HTML/CSS и ES-модули JavaScript,
Supabase Auth/PostgreSQL/Storage, SQL RPC. Главные файлы:

- `main.js` — загрузка, авторизация, обновление данных;
- `config.js` — общий state, DOM и клиент Supabase;
- `api.js` — запросы к таблицам и SQL-функциям;
- `render.js` — карта и объекты;
- `ui.js` — большой модуль интерфейса (~508 КБ);
- `economyEngine.js`, `militaryEngine.js`, `modifierSystem.js` — правила;
- `rules_mechanics.txt`, `wiki-drafts/` — описание игры;
- `supabase/` — 138 SQL-файлов, многие переопределяют функции.

Механики: государства/династии/сословия, экономика и производство, торговля,
религии и культуры, армии/флот/осады/командиры, колонизация, шпионаж, модификаторы,
административная смена сезонных ходов. Экономический ход рассчитывается в
браузере администратора, затем сохраняется SQL RPC. Есть административное
подтверждение боёв. Не все базовые таблицы определены в SQL репозитория;
полного воспроизводимого развёртывания старой базы пока нет.

Старая карта: 257 провинций. `map.png` — видимая подложка,
`color_map.png` — уникальный RGB на провинцию, `provinces_meta.json` — RGB→ID и
центр подписи. Пиксель скрытого Canvas определяет ID, данные берутся из базы.
Соседство строится сканированием растра с допуском до 2 чёрных пикселей границы.
Эту эвристику нельзя механически переносить на новую маску без пустот.

## Новая исходная карта и требования

`fauxlore.png` — оригинал пользователя, RGBA 10000×10000, НЕ изменён.
Провинции суши залиты бежевым, моря прозрачные. Между областями контуры:
чёрные на суше и тёмно-синие на море (последнее обнаружено по реальным пикселям).
Внешний фон также прозрачный. Некоторые острова присоединены к большим
сухопутным областям тонкой БЕЖЕВОЙ перемычкой толщиной 1 пиксель. Перемычки
нужно сохранять: они задают единую провинцию, не удалять морфологией или шумодавом.

Пользователь хочет отказаться от видимой растровой подложки: пиксели старых
контуров тоже должны принадлежать провинциям, без щелей. Это выполнено.
Техническая маска остаётся растровой; векторные полигоны пока НЕ создавались.

## Реализованный генератор маски

`tools/build_province_mask.py`, зависимости NumPy и Pillow:

```sh
python -m pip install numpy pillow
python tools/build_province_mask.py fauxlore.png map-data
python tools/test_province_mask.py
```

Подробности в `tools/MAP_PIPELINE.md`. Генератор:

1. Выделяет сушу по R≥230, G≥200, B≥180, A≥128; море — A=0.
   Остальные пиксели — контуры/помехи. Пороги подобраны под этот файл.
2. На исходном разрешении размечает 4-связные компоненты отдельно для суши и моря.
   Использует горизонтальные отрезки и union-find, не объект Python на пиксель.
   Диагональное касание само по себе не объединяет провинции.
3. Исключает ТОЛЬКО крупнейшую прозрачную компоненту у края как внешний фон.
   Другие прозрачные области у края — обрезанные морские провинции, сохраняются.
4. Убирает отдельные сухопутные компоненты исходной площадью 1–3 пикселя:
   пользователь подтвердил, что это артефакты, и поручил отдать их соседям.
   Это не затрагивает перемычки в больших компонентах и малые морские области.
5. Одновременно расширяет семена провинций на контуры и удалённые артефакты
   по 4 соседям (манхэттенское расстояние). При равенстве выигрывает меньший ID.
   Исходные семена остальных провинций неизменны. Изолированные штрихи без пути
   к семенам получает ближайшая провинция по евклидову расстоянию.
6. Сохраняет маску, метаданные, превью и отчёт. Проверяет PNG round-trip.

Итог ПОСЛЕ удаления артефактов:

- **5750 провинций: 4596 суша, 1154 море**.
- Удалены 10 сухопутных компонентов, всего 11 исходных бежевых пикселей.
- Удалённые ID: 1071, 1152, 1183, 1557, 1784, 2659, 2917, 3193, 3871, 5608.
- **ID остальных сохранены**, нумерация с пропусками, максимальный ID 5760.
  Не использовать количество провинций как максимальный ID!
- 1 107 808 исходных пикселей контура распределены, незаполненных — 0.
- Ещё 15 микроскопических МОРСКИХ областей отмечены в отчёте; их пользователь
  удалять не поручал. Они сохранены.

Выходные файлы в `map-data/`:

- `province-ids.png` — RGB 10000×10000, ID = (R<<16)|(G<<8)|B, 0 — внешний фон;
- `provinces.json` — ключ `#RRGGBB`, поля id, kind=land/sea, center, bbox,
  area (после распределения), seed_area (исходная площадь);
- `province-preview.png` — уменьшенное цветное диагностическое превью;
- `terrain-preview.png` — превью классификации суша/море;
- `report.json` — проверки, удалённые ID/координаты/получатели пикселей,
  оставшиеся малые области и крупнейшие провинции.

Ограничения: разрыв контура может слить области, авторский замысел алгоритм
не восстанавливает. Центр — среднее пикселей площади, может быть вне вогнутой
провинции. ID стабильны для текущего исходника; изменение рисунка может сдвинуть
нумерацию, понадобится сопоставление областей до привязки живых игровых данных.
Узкие бежевые перемычки остаются частью геометрии суши.

## Реализованный браузерный просмотрщик

Файлы `index.html`, `viewer.css`, `viewer.js`, инструкции в `README.md`.

- Загружает только новую маску и метаданные, не `fauxlore.png` и не старую базу.
- WebGL 2: массив RGB8-текстур плитками до 2048×2048; nearest/texelFetch сохраняет ID.
- Шейдер задаёт бежевую сушу, синие моря, вариации оттенка и жёлтое выделение.
  Границы рисуются по переходам ID без исходной подложки.
- GPU picking: отдельный FBO 1×1 возвращает точный RGB/ID по нажатию.
- Canvas экранного размера только для подписей.
- Перетаскивание мышью/пальцем, зум колесом/кнопками/двумя пальцами,
  двойное нажатие для приближения, «Вся карта».
- «Показать ID»/«Скрыть ID»: на малом масштабе часть подписей отсекается
  по сетке для уменьшения наложений, крупные и выбранная приоритетны.
- Поиск ID через форму или Enter: выделение и приближение по bbox.
- Нажатие на карту: ID, суша/море, площадь в пикселях (не км²!).
- Панель сворачивается; на экране уже 600px изначально свёрнута.
- Ошибки загрузки/нет WebGL/не найден ID показываются в статусе.

Проверено в реальном встроенном браузере: загрузка 5750 провинций, поиск 1550,
показ номеров, выбор 1501 нажатием на видимую область, перетаскивание и колесо,
кнопки масштаба/общий вид, сообщение об удалённом ID 1071. `node --check viewer.js`
прошёл. Проверки генератора прошли на маленьких примерах и полной карте.
Скриншот результата — `viewer-preview.png`. `map-preview.png` — ранний обзор
исходника; для работы сайта оба файла не требуются.

Производительность: маска сжата компактно, но GPU RGB8 100M пикселей занимает
около 300 МБ плюс временное декодирование. Это не полностью потоковый тайловый
рендер: сейчас загружаются все плитки. На слабых устройствах возможны ограничения.
При сильном приближении видна пиксельная геометрия; векторизация и LOD не сделаны.

## Обсуждение базы и размещения — решения пока не утверждены

У Fauxlore сейчас НЕТ серверного API, базы, авторизации, постов или расчёта ходов.
Не путать рекомендации из беседы с реализованными функциями!

Обсуждали Supabase Free + GitHub Pages. 5750 строк провинций — небольшой объём;
геометрия должна оставаться статическими файлами, а не 100M строк базы. Основные
риски — полные снимки мира на каждом ходу, вложения, многократная загрузка таблиц,
трафик и служебные логи. Для новой архитектуры нужны кэширование, пагинация,
обновления после действий, остановка polling в скрытой вкладке, ограниченные retry.

Пользователь показал расход действующего проекта Supabase (скорее старого,
не считать его автоматически настроенным для Fauxlore): БД 40/500 МБ,
egress 0.25/5 ГБ, 14 MAU, Storage 0/1 ГБ, Log Ingestion 0.30/1 ГБ,
Log Query 19.7/100 ГБ. Регистрация открылась 14 октября, зарегистрировались 8.
До 14 октября около 4–7 МБ логов/день, потом ~25–30 МБ, 16 октября пик 57.498 МБ.

Важные пояснения: ingestion — накопленный объём принятых логов за расчётный
период, не размер базы и не объём актуально хранящихся журналов. Запросы к API
могут создавать служебные логи; egress отдельно считает отправленные данные.
Log Query — просканированный при чтении журналов объём. Не экстраполировать
строго пропорционально зарегистрированным игрокам: смешаны разработка и активность.
Причину роста не исследовали: к рабочей базе/логам не подключались.

Официально проверено 18.10.2026: новые лог-квоты Supabase в soft launch,
enforcement пока не включён, для организаций до 25.09.2026 grace period до начала
2027, для новых может закончиться раньше. Эти сведения и тарифы перепроверять:
https://supabase.com/changelog/logs-usage-based-pricing
https://supabase.com/docs/guides/platform/manage-your-usage/logs-ingest
https://supabase.com/docs/guides/platform/manage-your-usage/logs-query

Пользователь заинтересовался локальным PostgreSQL с последующим переносом на
арендованный сервер. Рекомендация: PostgreSQL + свой серверный API, браузер
не подключать напрямую к PostgreSQL. Локально можно разработать всё и перенести
через миграции, pg_dump/pg_restore, конфигурацию приложения и пользовательские файлы.
Альтернативы обсуждены: self-hosted Supabase и SQLite. Выбор ещё НЕ утверждён.

Для 15–30 игроков рекомендован стартовый VPS/VDS: 2 vCPU, 4 ГБ RAM,
40–60 ГБ SSD/NVMe, Linux, API и PostgreSQL на одной машине. Это предварительная
оценка для собственного API, НЕ гарантия и НЕ sizing полного self-hosted Supabase.
Нужны реальные тесты расчёта хода. Физический dedicated пока избыточен.
Ориентир опубликованных тарифов Selectel на 18.10.2026: 2/4/50 — 650 ₽/мес,
4/8/80 — 1100 ₽/мес, в странице заявлено 3 ТБ внешнего трафика. Бюджет с копиями
предварительно 1000–2000 ₽/мес, домен отдельно. Перепроверять перед покупкой:
https://selectel.ru/services/cloud/vps-vds/ . Сервер не арендован.
Резервные копии хранить вне основной машины, настраивать ротацию логов.

## Git и передача

на master, а в GitHub уже был `main` с `0dfc24e` (Create README.md).

содержательный README сохранён. Сегодняшние результаты и этот файл включаются
в один новый коммит поверх существующего main и отправляются в origin/main.
Секретные `.env`, Python cache и node_modules исключены через `.gitignore`.
Старый проект переносится как submodule, не копия его истории/файлов в основном Git.
